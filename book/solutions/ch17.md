- Three elements give eleven categories (S and R for the display, all six for the adapter, T, I and D

## Exercise 17.2: A token store that fails closed

```{.cpp include="exercises/ch17/e2_token_roles/solution/access.cpp" snippet="check"}
```

**Key points.**

- Fail closed: list what is allowed (`hello`, `auth`, `status`) and give every other command,
  including tomorrow's, the operator role.
- An unknown role is an error, never a default role; a short digest, uppercase hex, extra fields and
  duplicates are signs of a damaged or tampered file and stop the server with the line number.
- No early exit and no `==` on secrets: the comparison runs once per entry for every token. Refusing
  malformed tokens before hashing keeps the comparison's input to one length and costs nothing.
- Counting comparisons is a deterministic test of what the code is responsible for. It does not
  prove that the comparison itself takes constant time (that is OpenSSL's `CRYPTO_memcmp`, a SOUP
  requirement), nor what the optimizer did.

**Common wrong answers.** A `std::map` lookup by digest (fast, and its time depends on the
secret); `return` inside the loop with a comment "constant time enough"; an unknown role mapped to
`observer` "because it is harmless" (an observer can read every file path in the status).

- On the threat model's tree, with every requirement verified and every assumption held, the only

## Exercise 17.5: Secure defaults for IPv4 and IPv6


**Key points.**

- Decide on bytes, not text: `inet_pton` accepts exactly the numeric forms, and IPv6 addresses are
  compared as 16 bytes, so `0:0:0:0:0:0:0:1` is `::1` and `127.0.0.1.nip.io` is not an address.
- `localhost` is a name, resolved by `/etc/hosts` or DNS, which can change between the check and the
  bind. A security decision is made on what will be bound.
- The IPv4-mapped form is loopback only when its IPv4 part is; the wildcards are every interface.
- Beyond loopback, TLS alone is not enough (an encrypted channel to anyone), and `--no-auth` is
  refused.
- A `string_view` may hold a NUL that the C string passed to `inet_pton` would cut off; copy and
  refuse it.

**Common wrong answers.** `starts_with("127.")`; `getaddrinfo("localhost")` in a security check;
IPv6 compared as strings; `0.0.0.0` treated as "local because it includes loopback".

1. A security threat becomes a safety risk when an attack is a cause in a hazard's sequence of
   events. For H-08: a process on the PC or the network connects to the control port and sends
   `stop` or `configure` (the attack), so a scan is stopped or acquired with other settings (the
   hazardous situation), which leads to a repeated scan with its dose or a quantitation error (the
   harm).
2. At least the NTIA minimum elements for each component: supplier, name, version, another unique

   a scanner would report every fixed vulnerability as open, and the triage would drown in false
   findings.
3. External entities (S, R), processes (S, T, R, I, D, E), data stores (T, R, I, D) and data flows

4. So that a copy of the server's token file, in a backup or a support bundle, lets nobody in. A
   token is 256 random bits, so there is nothing to guess and a fast hash is enough; a slow hash
   protects low-entropy secrets that people choose, which tokens are not.
5. A command the function does not know needs the strictest role, operator. With the opposite
   default, a command added later without thought for roles would be open to observers, and to
   anyone if authentication were also off.
6. Because the token is the secret; sending it before verifying the server sends it to whoever
   answered, including a program that bound the port first or a machine in the middle. An
   unverified TLS connection protects against passive eavesdroppers, not against an active one who
   impersonates the server.
7. A 1.x client does not authenticate, so every command it sends would now fail with

   what is wrong.
