## Exercise 23.1: Where did the datagrams go?

```{.python include="exercises/ch23/e1_where_dropped/solution/where_dropped.py"}
```

**Key points.**

- Find `/proc/net/snmp`'s columns by name. Kernels add columns (`InCsumErrors`, `IgnoredMulti`
  and `MemErrors` came later than the others), and a parser that counts positions reads the
  wrong number after an update without any error.
- The softnet counters and the socket's drops are 32-bit; subtract modulo 2^32^.
- The verdict is the first layer with drops, in the order a datagram meets them, because a drop
  upstream removes load downstream. Fix that layer and measure again.
- Unknown is not zero: a layer that cannot be read is `None`, and the verdict skips it without
  claiming it was clean.
- The host's `RcvbufErrors` minus the socket's drops is the drops of other sockets: on a DAQ PC
  that should be zero, and when it is not, another program competes for the host.

**Common wrong answers.** Taking the layer with the most drops as the verdict. Reading the softnet
columns as decimal. Reporting 0 for the card when the snapshot has no card statistics. Finding the
socket by its port, which another socket may share with `SO_REUSEPORT`, instead of its inode.

## Exercise 23.2: Read the kernel's drop count

```{.cpp include="exercises/ch23/e2_rxq_ovfl/solution/rxq_ovfl.cpp"}
```

**Key points.**

- Walk the control messages with `CMSG_FIRSTHDR` and `CMSG_NXTHDR`, and check level, type and
  length; another option (a time stamp) may come first.
- `MSG_CTRUNC` means the control buffer was too small and something is missing; do not trust a
  partial answer.
- Copy the value out with `memcpy`: `CMSG_DATA` is not aligned for every type.
- Unsigned subtraction handles the wrap; no branch is needed.
- The count is written when a datagram is *queued*, so drops after the last queued datagram are
  carried by nothing. The test's first batch shows it, and MiniDAQ reads `/proc/net/udp` for that
  reason.

**Common wrong answers.** Reading `*reinterpret_cast<uint32_t*>(CMSG_DATA(c))`. Ignoring the
level, so that an IP-level message with the same type number is taken. Treating a smaller value
as an error instead of a wrap.

## Exercise 23.3: Size a receive buffer

```{.cpp include="exercises/ch23/e3_buffer_sizing/solution/buffer_sizing.cpp"}
```

**Key points.**

- The limit is twice the granted size, and each datagram is charged its truesize, not its
  payload. Divided by the payload, a 4 MiB buffer would seem to hold 5,698 full-size datagrams;
  by the measured charge it holds 3,639, and for jumbo datagrams the payload overestimates the
  capacity by a factor of two (1,022 against 504).
- The charge is a measured average, and the kernel's accounting reserves memory in pages, so the
  estimate rounds down and is at most one datagram short.
- The stall a buffer survives depends on the rate during the stall: 0.74 s at the real-time rate,
  7.7 ms for the same data in a burst.
- A request above `rmem_max` is not an error from the kernel; it is a smaller buffer. The function
  that sizes it must say so.

**Common wrong answers.** Dividing the granted size, not twice it, by the charge, which is off by
a factor of two. Dividing by the payload. Sizing for the average rate.

## Exercise 23.4: A batch receiver

```{.cpp include="exercises/ch23/e4_batch_receiver/solution/batch_receiver.cpp"}
```

**Key points.**

- Allocate every buffer in the constructor, and set up the headers again before every call: the
  kernel writes `msg_len`, `msg_flags` and `msg_controllen` back.
- One byte more than the largest datagram makes a datagram that is too long visible, together with
  `MSG_TRUNC`; never return more than the largest size.
- `EAGAIN` is the normal result of a non-blocking receive on an empty socket, not an error.
- Keep `errno` for the caller; the data path does not throw.
- Batching costs nothing and helps where system calls are expensive; on the book's machine it
  saved 5%, because the copy and the memory management dominate.

**Common wrong answers.** Allocating the buffers in `receive`. Reusing the message headers without
resetting `msg_controllen`, so that the second call has no room for control messages and every
drop count reads 0. Treating `EAGAIN` as an error. Returning a span of `msg_len` bytes for a
truncated datagram, which can exceed the buffer.
