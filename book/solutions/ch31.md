## Exercise 31.1: Coincidences per crystal pair, through a memory map

```{.python include="exercises/ch31/e1_pair_counts/solution/pairs.py"}
```

**Key points.**

- Map the file with `np.memmap` as bytes, read the header's length, and walk the blocks by their
  record counts; view each block's records as the structured dtype, in place.
- Order each pair before keying it: lower id times the number of crystals plus higher id. A line of
  response is the same whichever crystal saw the earlier single.
- Drop the delayed coincidences (bit 15 of crystal_a) and the tags (crystal_a 0x7FFF with bit 15
  clear) before counting.
- Count keys with `np.unique(..., return_counts=True)`, once for the whole file.

**Common wrong answers.** Keying by (crystal_a, crystal_b) as stored, which splits each pair under
two keys, about half of its counts under each. Masking only the delayed bit and keeping the tags,
whose crystal_b is a tag kind. Clearing bit 15 and keeping the delayed coincidences, which are
randoms. Reading the records with a dtype whose fields do not add up to 16 bytes, which shifts every
field after the wrong one.

## Exercise 31.2: A timing fit you can trust at low counts

```{.python include="exercises/ch31/e2_timing_fit/solution/timing_fit.py"}
```

**Key points.**

- Model the expected counts per bin, integrated over the bin with the error function, so the area is
  a number of counts.
- Minimize the Poisson deviance, with the `n ln(n / mu)` term zero where a bin is empty.
- Step by Fisher scoring: solve `I step = U` with `U = J^T (n / mu - 1)` and `I = J^T diag(1 / mu)
  J`; halve a step that does not lower the deviance; keep the background at or above zero.
- Take the errors from the inverse of `I` at the minimum, and the FWHM's error by propagating the
  covariance.
- Compute `J` by central differences with a step that does not vanish for a parameter near zero: the
  timing mean is near zero by design.

**Common wrong answers.** Least squares weighted by the counts, which biases a weak peak (the
starter: 394 on average for 300, from four runaway fits and 296 that average 270). A Poisson fit
whose errors are one over the square root of the diagonal of `I`, which ignores the strong
correlation of the area and the background and makes the pulls too wide. A step relative to the
parameter's value alone, which for a mean of 0.01 ps is so small that the derivative is rounding and
the fit stalls near its minimum.

## Exercise 31.3: The per-crystal timing histogram in C++, behind a Python boundary

```{.cpp include="exercises/ch31/e3_histogram/solution/dthist.cpp"}
```

**Key points.**

- Compute the bin with a floor division: C++'s `/` truncates toward zero, so times just below `lo`
  would land in the first bin.
- Take `py::array_t<std::int32_t, py::array::c_style | py::array::forcecast>`, so an int64 array is
  converted instead of refused. The format bounds both fields to 32 bits; for an unbounded quantity,
  take int64 instead.
- Check the lengths and the crystal ids, and raise `ValueError` with the entry and the id. Raise
  after the loop, with the GIL held again, not inside the loop where it is released.
- Release the GIL around the loop, which touches only the views taken before it.

**Common wrong answers.** Truncating division, which the reference test on random data does not see
(no entry falls between `lo - bin` and `lo`) and the edge test does: three entries in the first bin
instead of one. No `forcecast`, which turns an int64 array into a `TypeError` naming the signature.
Throwing from inside the released section, which builds a Python exception without the GIL. Counting
into a Python list or calling NumPy inside the loop, which gives back the speed the C++ was for.
