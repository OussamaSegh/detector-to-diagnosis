## Exercise 37.1: Nothing of the patient leaves

```{.python include="exercises/ch37/e1_deidentify/solution/deidentify.py"}
```

**Key points.**

- Build the output from a list of what to keep; an attribute nobody listed is dropped, whatever
  its name. Private and free-text attributes are where identity hides.
- Pseudonyms from a keyed hash (HMAC) of the patient ID: stable for one patient and key, useless
  without the key. A plain hash of an ID can be reversed by hashing every possible ID.
- One date shift per patient, from the same HMAC, for every date: intervals and order survive,
  calendar dates do not. The birth date is dropped.
- UIDs remapped consistently under 2.25, so that references between objects still hold.

**Common wrong answers.** Deleting a list of known identifiers and keeping the rest. A random
pseudonym per call, which breaks the link between two files of one patient. A random shift per
date, which breaks the decay between the study and the acquisition. Dropping the UIDs, which
breaks every reference between objects.


**Key points.**

- A reference is a word of a code span or a fenced block whose first component is a top-level
  entry of the repository; that one rule removes prose, options and URLs.
- Strip a trailing slash, a `:line` suffix and punctuation before checking.
- Placeholders (`NN`, `X.Y.Z`, `<name>`, `*`) become a regular expression over the repository's
  paths; the reference is fine if one path matches.
- Test names are checked against `add_test(NAME ...)` in the CMake files, without a build.

**Common wrong answers.** Every code span with a slash, which reports `a/b` and URLs. Treating a
pattern as a path, which reports every placeholder. Ignoring fenced blocks, where most commands
are. Running `ctest -N`, which needs a configured build the context file's reader may not have.

## Exercise 37.3: A review written as tests

```{.cpp include="exercises/ch37/e3_review_by_tests/solution/test_review.cpp"}
```

**Key points.**

- One test per clause of the requirement, each with the values on both sides of its edge: the
  window's edge and one picosecond past it, a window of 0, the wrap in both directions and one
  picosecond across it, both argument orders, timestamps just past the counter, a window of half
  the circle and one less, distances beyond 32 bits.
- Write the tests from the requirement without looking at the mutants; every mutant is caught
  because every clause has its edge tested.
- Take the constants from the subject so that the tests follow the counter's width.

**Common wrong answers.** Typical values only (2 ns in a 4 ns window), which every mutant passes.
A wrap test in one direction only, which lets the one-way distance through. A window of 4 ns at the
wrap, which hides the period that is off by one; only windows of 0 and 1 show it. No timestamp above
the counter's range, which lets the masking version through.
