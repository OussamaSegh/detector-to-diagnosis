**Key points.**

- Try `%.Ng` with N from 16 down and keep the first result that fits in 16 characters: it keeps
  the most digits the field allows. A value with an exponent still keeps at least 10 significant
  digits, so the relative error stays below 5e-10.
- Compute the stored values with `float(text)`, the slope as written, not the slope you computed.
  The bound of half a slope is then a property of the code, whatever the value.
- Clip before the cast to `uint16`: a cast of an out-of-range float wraps silently.
- Refuse NaN and infinity, and give an empty plane a slope of 1, so that no division by zero and
  no meaningless text reach the file.

**Common wrong answers.** A fixed number of decimals, which turns the phantom's slope of 1.4e-7
into `0.000000` and every pixel into 0. `repr` of the float, which can be 18 or more characters.
Dividing by the computed slope, which is right for most values and off by one step for a few.
Truncating a long text instead of formatting it shorter.

## Exercise 35.2: Where is this pixel in the patient?


**Key points.**

- One table of signs per patient position (HFS: x, -y, z; FFS: -x, -y, -z), and the array, the
  position of the first pixel and the orientation all computed from it, so that they cannot
  disagree.
- Rows go out top down, so the column direction of the orientation points to the back of the
  patient (0, 1, 0 in LPS for HFS).
- Pixel Spacing is the spacing between rows first, then between columns.
- Refuse an unknown position: a guess is a mirrored image.
- Test with non-square pixels and an off-axis point; square pixels and a centered object pass
  every one of the starter's mistakes.

**Common wrong answers.** Swapping only the sign of x for FFS and forgetting z, which puts the
slices in the wrong order. Flipping the rows without changing the orientation, or the other way
around. Checking the result with the writer's own reader, which agrees with any consistent
mistake.

## Exercise 35.3: Messages out of fragments

```{.python include="exercises/ch35/e3_pdata/solution/pdata.py"}
```

**Key points.**

- Two layers: one generator walks the PDVs of a PDU, another applies the rules of a message
  (command first, its last fragment, then the data set to its last fragment).
- Check each PDV's length against what is left of its PDU before slicing; a Python slice past the
  end returns fewer bytes, not an error.
- The message's presentation context is fixed by its first fragment; another context in the middle
  is an error.
- Input that ends in the middle of a message is an error, not a short data set: the archive must
  store nothing, so that the sender, without a success status, sends the instance again.

**Common wrong answers.** Taking each PDV as a whole message. Ignoring the command bit and
treating a data set fragment before the command's last one as part of the command. Accepting a
truncated stream as the end of the association. No limit on what one message may buffer, which a
product must set from the largest object it accepts.
