**Key points.**

- Declare what the C++ reads: `py::array_t<double, py::array::c_style | py::array::forcecast>`.
  pybind11 then passes a C-contiguous float64 array, the caller's own or a converted copy.
- Check `ndim()` before any `shape(d)`, and the lengths before any element; put both shapes in
  the message.
- Allocate the result. A function that computes something does not write into its arguments.
- Release the GIL around the loop only; allocate before and return after.

**Common wrong answers.** Indexing `data()` of an array taken without `c_style`, which reads a
Fortran-ordered or strided array scrambled. Scaling in place, which changes a float64 caller's
array and not an int32 caller's. Raising `IndexError` (from `shape(1)` on a vector) where the
caller passed a wrong argument.

```{.cpp include="exercises/ch29/e2_threads/solution/parallel.cpp"}
```

**Key points.**

- Chunk boundaries `count * k / t` cover `[0, count)` exactly, whatever the remainder, and differ
  by at most one in size. Use at most `count` threads, and the calling thread when one is enough.
- Give each thread its own output and sum the outputs in thread order: no lock, no race, and the
  same bits on every run with the same number of threads.
- Check the indices before starting the threads: an exception thrown inside a `std::jthread`
  ends the program.

**Common wrong answers.** `chunk = count / threads`, which leaves the last `count % threads`
indices to nobody and, with more threads than indices, does nothing at all. One shared output,
which loses additions when two threads update the same element, on some runs only.
`std::atomic<double>` for every element, which is correct and slow, because every addition
contends for the same cache lines.

## Exercise 29.3: Is the second implementation the same?

```{.python include="exercises/ch29/e3_equivalence/solution/equivalence.py"}
```

**Key points.**

- Compare the geometry first, so that a mismatch is reported as one.
- Use random data in both directions: a random image for forward, a random sinogram for back.
  A symmetric object hides the mistakes that symmetry maps onto themselves.
- Measure the error relative to the largest value, against a tolerance derived from the precision
  the implementations are allowed to differ by.
- Check the candidate's own dot-product test as well.

**Common wrong answers.** A centered disc, which projects the same in every view and both ways
along `s`. `np.array_equal`, which refuses the float32 projector. Comparing forward only, which
accepts any backprojector.
