## Exercise 28.1: A backprojector that is the adjoint of its projector

```{.python include="exercises/ch28/e1_adjoint/solution/adjoint.py"}
```

**Key points.**

- Read the matrix off the projector: a pixel's column has two entries, in bins `lo` and
  `lo + 1`, with weights `1 - frac` and `frac`. The transpose gathers from the same two bins with
  the same weights, which is linear interpolation of the sinogram at the pixel's `s`.
- Compute the weights in one place (`_splat`) and use them in both directions, so that the pair
  cannot drift apart when one of them changes.
- The sensitivity is `back(mult)`: a pixel near a corner loses part of its weight outside the
  bins (27.8 of 36 views for pixel (0, 0)), and a bin with `mult = 0` adds nothing.

**Common wrong answers.** The nearest bin, which fails the dot-product test by 0.25% and still
reconstructs a centered disc well. A sensitivity equal to the number of views, which takes a
corner pixel to 0.77 of its true value in one iteration started from the truth.

## Exercise 28.2: The corrections in the model

```{.python include="exercises/ch28/e2_model/solution/model.py"}
```

**Key points.**

- Three changes to plain MLEM: the expected counts `mult * forward(x) + add`, the backprojected
  ratio weighted by `mult`, and the sensitivity `back(mult)`. The counts `y` are never divided,
  subtracted or clipped.
- Start from an image that is 1 where the sensitivity is positive and 0 elsewhere: a pixel that
  no measured line sees cannot be estimated.
- The likelihood is evaluated with the full model, and it never decreases.

**Common wrong answers.** Clipping `(y - add) / mult` at 0, which raises the corrected sum to
1.70 times the unclipped one at these counts and puts the excess into the background. Setting
the gaps to 0 and keeping them in the update, which draws stripes through the disc. Dividing the
ratio by `mult` instead of multiplying the backprojected ratio by it, which is the pre-correction
again in another place.

## Exercise 28.3: Ordered subsets

```{.python include="exercises/ch28/e3_subsets/solution/subsets.py"}
```

**Key points.**

- Every `count`-th view in each subset, so that each spans the half turn; with 36 views in 5
  subsets the first has 8 views and the others 7.
- One sensitivity per subset, the backprojection of `mult` over that subset's views, computed
  once before the iterations.
- Refuse 0 subsets and more subsets than views with `ValueError`: both are a configuration
  error, not a case to guess at.

**Common wrong answers.** Consecutive blocks of views, 3.6% rms from MLEM after 4 iterations
against 0.39% for interleaved subsets. The full sensitivity divided by the number of subsets,
3.3% rms away with interleaved subsets and 21% with consecutive blocks, because the subsets have
different numbers of views and different factors.
