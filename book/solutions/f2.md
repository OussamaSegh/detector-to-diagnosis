# Modern C++, from C++11 to C++23 {#sol-chf2}

## Exercise F2.1: The spectrum with ranges and std::ranges::to

```{.cpp include="exercises/f2/e1_ranges_spectrum/solution/spectrum.hpp" snippet="spectrum"}
```

**Key points.** `in_window` returns a range adaptor that both `energies_in_window` and
`photopeak_fraction` reuse. The pipelines use a pointer to a member as the projection. The bins
are half-open, and the clamp keeps a value that rounds up to `bins` in the last bin. `to_vector`
calls `std::ranges::to<std::vector>` when `__cpp_lib_ranges_to_container` is defined (GCC 14) and
the iterator-pair constructor of a `std::views::common` range otherwise (GCC 13).

**Common wrong answers.** Calling `.size()` on a `filter_view`, which has none (use
`std::ranges::distance`). Passing a non-common view to the vector's iterator-pair constructor.
Closed bins `[lo, hi]`, which put the edge value in two bins or none.

## Exercise F2.2: A sinogram view in the shape of std::mdspan

```{.cpp include="exercises/f2/e2_sinogram_view/solution/sinogram_view.hpp" snippet="view"}
```

**Key points.** The view is a span and two extents. Row-major indexing, `angle * bins + bin`,
makes `row(angle)` a contiguous `subspan`. The constructor rejects a buffer whose size is not
`angles * bins`, so every later index computation is in range when the indices are. `at` checks,
`operator[]` does not. Constness belongs to `T`, as for `std::span`.

**Common wrong answers.** `angle * angles + bin` (the wrong extent). A `row` that copies into a
vector instead of returning a span. Making `operator[]` non-`const`, which forbids indexing a
`const` view of mutable data.

## Exercise F2.3: A generator over a list-mode file

```{.cpp include="exercises/f2/e3_generator/solution/listmode.hpp" snippet="singles"}
```

**Key points.** Each function is a loop with a `co_yield` where the eager version had a
`push_back`. The coroutine pauses at every `co_yield`, so the caller's loop drives the decoding:
three singles taken, three records decoded. `in_window` takes its input generator by value and
pulls from it only as far as it must. An exception inside the coroutine is stored by the promise
and rethrown at the caller's `++`, after the singles already delivered.

**Common wrong answers.** Keeping the vector and yielding from it (still eager). Taking the input
generator of `in_window` by reference, which dangles when the caller passes a temporary.

## Exercise F2.4: A view that dangles

```{.cpp include="exercises/f2/e4_audit_dangling_view/solution/spectrum.hpp" snippet="fixed"}
```

**A model review.**

1. *`peak_region` views a temporary.* `counts()` returns a copy; the span views it and the copy
   dies at the end of the `return`. It also copies the whole histogram, the opposite of the
   specification. Input: any call. Fix: view `counts_`.
2. *`label` views a temporary.* `material_ + " spectrum"` is a new string that dies at the
   `return`. Nothing to view exists before the call, so return `std::string`.
3. *No bounds check.* `peak_region(2, 1)` wraps the count to a huge value; `last > size()` reads
   past the end. Check, or state and assert the precondition.
4. *The claims.* GCC 13 is silent on both functions at `-Wall -Wextra`; Clang 18 warns about the
   `string_view` only. A correct-looking plot is what undefined behavior often looks like.

**Decision.** Rejected; the fix above.

## Check yourself: model answers

1. **Returning a vector.** A returned temporary is constructed in the caller's object (guaranteed
   copy elision); a returned local is elided or moved, and a move copies three pointers.
2. **`shared_ptr`.** When several owners really share an object and none of them can say when
   it dies, such as a key read by several runs. A copy increments an atomic count, a contended
   memory operation when threads share it.
3. **`auto`.** References and top-level `const`. Write `auto&` or `const auto&`.
4. **Concepts.** The requirement is named in the interface and checked at the call, with an
   error that names it instead of one deep inside the template; overloads can be chosen by
   concept.
5. **A filter view iterated twice.** `filter_view` caches the position of its first matching
   element at the first `begin()`; if the elements change, the second iteration starts from the
   cached position, which may no longer match, and skips nothing it should have found before.
6. **`span<const T>` against `const vector<T>&`.** The span accepts any contiguous sequence
   (vector, array, part of either) and says that only the elements matter; the reference demands
   a whole vector.
7. **A paused coroutine.** In its frame, allocated when it is called (on the heap unless the
   compiler elides it). A generator is lazy because `initial_suspend` suspends before the body
   runs, and each `co_yield` suspends again.
8. **Modules.** GCC 13's support is incomplete and `import std;` is not available on the book's
   compilers (ADR 0035).
9. **`and_then`, `transform` on an error.** Neither calls its function; both return the error
   unchanged.
10. **`-std=c++23` differs.** A different standard library version (GCC 13's against GCC 14's),
    or Clang with libstdc++ where the library hides a feature from that compiler.
11. **Feature-test macros.** The library, not the compiler, decides, and a compiler can pair
    with several libraries; the macro states exactly whether the feature is there.
12. **`std::unreachable` on a register value.** A register can hold any value, including one the
    code does not expect; `std::unreachable` turns that into undefined behavior instead of a
    defined fallback.
