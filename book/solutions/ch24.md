# FPGA firmware and the interface contract {#sol-ch24}

## Exercise 24.1: Check a valid/ready handshake

```{.cpp include="exercises/ch24/e1_handshake/solution/handshake.cpp"}
```

**Key points.**

- A word is waiting at cycle `i` when cycle `i - 1` had valid and not ready. Only then are valid
  and data bound in cycle `i`; after a transfer, the next cycle is free, so back-to-back words
  are correct.
- Report the first broken rule of a cycle, with its cycle number, in the order of the trace: a
  firmware engineer will open the waveform at that cycle.
- A stall is back-pressure from the receiver; the longest run of stalls times the incoming rate
  is what the buffer in front of it must hold.
- Rule 4 (the sender does not wait for ready) prevents a deadlock that looks like an idle stream,
  so it is checked by reading the RTL or by an assertion in simulation, not from a trace.

**Common wrong answers.** Comparing every cycle's data with the previous one, which flags
back-to-back words. Counting a cycle with ready and without valid as a transfer. Resetting the
stall run on an idle cycle but not on a transfer.

## Exercise 24.2: Gray code across clock domains

```{.cpp include="exercises/ch24/e2_gray_code/solution/gray_code.cpp"}
```

**Key points.**

- `encode` is `b ^ (b >> 1)`; `decode` is the prefix XOR from the top bit down, which five
  shift-and-XOR steps compute for 32 bits.
- Consecutive Gray values differ in exactly one bit, including the wrap from the largest value of
  an n-bit pointer back to 0, so a sample taken while it changes is the old or the new value.
- The pointers have one bit more than the address so that a full FIFO (the pointers differ only
  in the top bit) and an empty one (equal) can be told apart; the count is the difference modulo
  twice the depth.
- A late write pointer makes the read side see fewer words than there are, never more: the
  design's safety comes from both sides being pessimistic.

**Common wrong answers.** Decoding with a single `g ^ (g >> 1)`, which is the encoding again.
Masking the difference to the address width, which makes a full FIFO look empty.

## Exercise 24.3: The board's output FIFO, cycle by cycle

```{.cpp include="exercises/ch24/e3_out_fifo/solution/out_fifo.cpp"}
```

**Key points.**

- Compute every decision of an edge from the state before it (`full`, `push`, `pop`, the flag),
  then apply them. That is what the flip-flops do, and it is why the model refuses an event into a
  full FIFO even when the link takes a word in the same cycle, as the listing does.
- The flag's set wins over the clear: an event lost in the cycle of a clear must not be forgotten.
- The model counts every lost event, which the board's one-bit flag cannot; the difference is why
  MiniDAQ's overflow count is only a lower bound.
- The board's numbers: a 4,096-word FIFO fills in 164 ms at 50,000 words per second over a
  25,000-word link, in 2.048 s at 27,000, never at 20,000; it drains in 164 ms when full.

**Common wrong answers.** Popping first and then testing `full` on the new count, which lets a word
in that the firmware refuses. Clearing the flag before setting it. Rounding the burst depth to
the nearest integer instead of up.

## Exercise 24.4: A counter wider than a register

```{.cpp include="exercises/ch24/e4_split_counter/solution/split_counter.cpp"}
```

**Key points.**

- High, low, high: if the high half is the same before and after the read of the low half, no
  carry happened in between and the pair is a value the counter held.
- Bound the attempts and report failure: a counter whose high half changes faster than the bus
  can read three registers never yields a consistent pair.
- A failed read is not a value; stop at the first one.
- In firmware, a shadow copy of the high half taken when the low half is read makes one read of
  each enough, but only low first and with nothing else reading in between, which the ICD must
  state.

**Common wrong answers.** Reading low then high once, which is off by 2^32^ at every carry that
falls between the reads. Retrying without a limit. Combining the low half with the second high half
when the two high halves differ, which is right only if the carry happened before the low read.
