# CMake and dependency management: the build as an interface {#sol-ch32}

## Exercise 32.1: Make a library installable

```{.cmake include="exercises/ch32/e1_install/solution/CMakeLists.txt"}
```

```{.cmake include="exercises/ch32/e1_install/solution/cmake/pulseConfig.cmake.in"}
```

**Key points.**

- Give the include directory per context: `$<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>`
  while building, `$<INSTALL_INTERFACE:${CMAKE_INSTALL_INCLUDEDIR}>` once installed.
- Make `PULSE_CHECKED` private: it is how the library is built, and a user that inherits it
  compiles the library's headers differently from the library.
- Install the target into an export set, the export set under the namespace `pulse::`, a
  configuration file made by `configure_package_config_file`, and a version file with
  `SameMajorVersion`, all under `${CMAKE_INSTALL_LIBDIR}/cmake/pulse`.

**Common wrong answers.** Only `INSTALL_INTERFACE`, which breaks every target of the same project
that links `pulse`: the relative path means nothing in the build tree. Exporting the targets as
`pulseConfig.cmake` with no version file, which `find_package` reads but which fails every request
that names a version. `AnyNewerVersion`, which accepts 2.0. A hand-written
`pulseConfig.cmake` with `${CMAKE_INSTALL_PREFIX}` in it, which names the prefix of the first
installation and fails the moved-installation test.

## Exercise 32.2: One command per configuration

```{.json include="exercises/ch32/e2_presets/solution/CMakePresets.json"}
```

**Key points.**

- Put `-fsanitize=address` in both the compile flags and the link flags: the instrumentation calls
  the sanitizer's runtime, which only the link brings in.
- Give each configuration a build preset, a test preset and a workflow preset of its name; the
  workflow runs configure, build and test in that order.
- Presets file version 6 is the first with workflow presets (CMake 3.25).

**Common wrong answers.** Only the compile flag, which fails to link with undefined `__asan_*`
symbols. A test preset without `configurePreset`, which CMake refuses. Forgetting that a preset's
`CMAKE_CXX_FLAGS` replaces the inherited value instead of adding to it: here `dev` sets no flags,
but where a base preset sets some, the sanitizer configuration silently loses them.

## Exercise 32.3: A header that costs a rebuild

```{.cpp include="exercises/ch32/e3_rebuild/solution/src/geometry.hpp"}
```

```{.cpp include="exercises/ch32/e3_rebuild/solution/src/geometry.cpp"}
```

**Key points.**

- Keep the two numbers the geometry needs instead of a copy of the configuration, so the class no
  longer needs `Config`'s definition.
- Declare `struct Config;` in the header and include `config.hpp` in `geometry.cpp`, where the
  constructor reads it.
- `main.cpp` still includes `config.hpp`, because it calls `default_config()`.

**Common wrong answers.** A forward declaration with the member `Config config_` kept, which does
not compile: a member needs the complete type. A `const Config&` member, which compiles and ties
the geometry to an object it does not own. Including `config.hpp` from `rings.hpp` instead, which
moves the dependency without removing it.
