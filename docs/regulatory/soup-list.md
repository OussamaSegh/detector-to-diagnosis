# MiniDAQ SOUP list

Version 3 (MiniDAQ 0.3.0-dev, Chapter 16). Status: draft for review.

SOUP is software of unknown provenance: software that MiniDAQ uses but did not
develop under its own process. This list identifies each item exactly, says why
MiniDAQ needs it, states what MiniDAQ requires of it, and records how its known
anomalies are reviewed. It is a teaching example, not a document of the manufacturer's
quality management system; your organization's procedure defines the real
content and the review records it needs.

The machine-readable counterpart is the CycloneDX SBOM generated by
`tools/make_sbom.py` from `cmake/Dependencies.cmake`. The test `tools.sbom`
fails if the SBOM does not validate, and `make_sbom.py` refuses a dependency
that has no entry with a license and a scope, so a new FetchContent dependency
cannot reach a release without someone adding it here and there. The test `docs.soup`
(`tools/check_soup.py`) fails if a pin or version in `cmake/Dependencies.cmake` is missing
from this list, or if a shipped item's known-anomaly review is not dated for the current
MiniDAQ minor version.

## 1. Items in the shipped software

| Field | nlohmann/json |
|---|---|
| Identification | nlohmann/json 3.12.0, release archive `json.tar.xz`, SHA-256 `42f6e95cad6ec532fd372391373363b62a14af6d771056dbfc86160e6dfff7aa` (pinned in `cmake/Dependencies.cmake`; 3.11.3 until change request CR-0002) |
| Supplier | Niels Lohmann and contributors, https://github.com/nlohmann/json |
| License | MIT |
| Used by | `minidaq_control` (configuration, control protocol, audit trail), `minidaq_server`, `minidaq_ctl`. Not used by `minidaq_core`; `tools/check_layers.py` enforces that. |
| Why | Decision record [ADR 0004](../adr/0004-json-library.md) |
| Functional requirements on it | Parses any byte sequence without undefined behavior; reports every malformed input as a catchable exception or a discarded value; round-trips the values MiniDAQ writes; replaces invalid UTF-8 on output when asked (`error_handler_t::replace`). |
| Performance requirements on it | None on the hot path. A control request of at most 64 KiB (`max_request_bytes`) is parsed in well under the 1 s a person waits for a response (assumption: confirm with team for real response-time requirements). |
| Hardware and software it needs | A C++11 compiler and standard library; header-only. |
| Safety class of the items that use it | B: `config`, `service`, `protocol`, `output`, `audit` and `server` ([architecture section 4](../architecture/architecture.md#4-software-items-and-layers)). |
| What its failure could cause | A configuration or command read wrongly (a wrong acquisition setting), a crash of the server during a run (a lost scan), a run record that does not say how the data was acquired. The hot path does not use it, so it cannot alter coincidences. |
| Risk controls outside it | Every value read is validated by MiniDAQ's own reader (types, ranges, unknown keys); the effective configuration is reported in `status` and stored in the audit trail and the run record, so a wrong setting is visible; the parser runs with exceptions caught or disabled; fuzzing under sanitizers. Chapter 15 links these to the hazards. |
| How MiniDAQ verifies its use | Unit tests of the configuration reader and protocol (`test_config.cpp`, `test_control_protocol.cpp`); the `fuzz_config` and `fuzz_protocol` fuzz targets under AddressSanitizer and UndefinedBehaviorSanitizer (Chapter 7). |
| Anomalies found by MiniDAQ | Numbers outside the range of `double`, such as `6e688`, raise `json::out_of_range` (406), not `json::parse_error`. MiniDAQ's reader caught only `parse_error`, and the configuration fuzzer found the resulting crash within seconds. This is documented library behavior, not a library defect; the reader now catches `json::exception` (test `Config.NumberOverflowIsAnErrorNotACrash`). |
| Known-anomaly review | Before each release: read the library's issue tracker and release notes for the pinned version and any later ones, and evaluate each reported defect against the requirements above. Record the result below. |
| Last review | 2026-10-25, for MiniDAQ 0.3: 3.12.0, the pinned version, has no later release; the fixes on its development branch were read (record in [section 4](#4-known-anomaly-reviews)). Result: none affects a requirement above. |

The platform that the shipped programs run on (C++ standard library, C
library, Linux kernel interfaces) is also SOUP, but it is supplied by the
target system rather than pinned by this repository. Its identification and
qualification belong to the platform definition (Chapter 25).

## 3. Changing this list

Adding, removing or upgrading a SOUP item is a change like any other: a pull
request that updates `cmake/Dependencies.cmake`, this list, `KNOWN` in
`tools/make_sbom.py` and, for a new shipped item, an ADR. The reviewer checks
the license, the requirements above against the new version's release notes,
and the known-anomaly review.

## 4. Known-anomaly reviews

### 2026-10-25: nlohmann/json 3.11.3, for MiniDAQ 0.3

Reviewer: the book's author (a real review names the reviewer and is approved under the
procedure). Sources: the release notes of
[v3.12.0](https://github.com/nlohmann/json/releases/tag/v3.12.0) (2025-04-11), the only
release after 3.11.3 at the date of the review. They list no vulnerability. Not reviewed:
the open issues of the tracker, which a real review also reads (verify: the open issues
reported against 3.11.3 before each release).

| Fix in 3.12.0 (issue or pull request) | Does MiniDAQ use the affected feature? | Effect on MiniDAQ's requirements |
|---|---|---|
| `iteration_proxy` becomes a forward iterator (#4371, #4372) | Uses `items()` in range-for loops only | None |
| Enums with an unsigned underlying type converted wrongly (#4236, #4237) | No: enums are written with `to_string` | None |
| GDB pretty printer and natvis (#4343, #4309, #4451, #4438) | Debugging aids only | None |
| Crash when `nullptr` is passed as `FILE*` to `parse` (#4485, #4487) | No: parses strings only | None |
| Integers parsed as floats when `errno` holds `EINTR` (#4506) | Yes: the control server parses requests after `poll()`, which can return `EINTR` (verify: the exact condition in #4506) | An integer read as a floating-point number. The configuration reader requires integers (`is_number_integer`), so the value is rejected with a `config_error`; no wrong setting is accepted. A request `id` might be echoed as `2.0`. Fails safe; recorded as known anomaly MDQ-PR-005. |
| SAX output of floats depends on the locale (#4505, #4084) | No SAX interface | None |
| Default-constructed iterators cannot be compared (#4512, #4493) | No | None |
| `get_ptr` for unsigned integers (#4525, #4475) | No | None |
| Regression of #2755, `EOF` replaced by `char_traits` (#4532) | Input adapters for strings | None known (verify: the regression's trigger) |
| Extended diagnostics trigger an assertion (#4537, #3915) | No: `JSON_DIAGNOSTICS` is not defined | None |
| `NLOHMANN_DEFINE_TYPE_INTRUSIVE_WITH_DEFAULT` with an empty object (#4507, #4508) | No | None |
| Integer comparison modernized (#4577, #4559) | Internal | None |
| Empty tuple serialized as `null` instead of `[]` (#4594, #4530) | No tuples | None |

Decision: keep 3.11.3 for MiniDAQ 0.3.0. Upgrading to 3.12.0 is a SOUP change (section 3)
that would remove anomaly MDQ-PR-005; it is planned with the rest of the change process in
Chapter 16.

Follow-up (Chapter 16): the "verify" above was resolved by reading both versions of the lexer.
3.11.3 sets `errno` to 0 immediately before `strtoull` or `strtoll` and treats any nonzero
`errno` afterwards as a failed integer conversion; 3.12.0 treats only `ERANGE` as one. A value of
`errno` left by an earlier `poll()` therefore cannot trigger the defect, contrary to what this
review assumed; it needs a C library that sets `errno` during a successful conversion, which
POSIX forbids (verify: the C library of the target platform). MDQ-PR-005 was corrected
accordingly, and the upgrade was made by change request CR-0002.

### 2026-10-25: nlohmann/json 3.12.0, for MiniDAQ 0.3

Reviewer: the book's author. Sources: the release history at json.nlohmann.me (3.12.0 of
2025-04-11 is the latest release; its notes say that no public API was removed or renamed) and
the list of changes on the development branch, not yet released, which names the defects found
in 3.12.0 (verify: each against the issue tracker, which this review could not read). The archive
was checked against the tag: its `single_include/nlohmann/json.hpp` is byte-identical to the one
at tag `v3.12.0`.

| Defect fixed after 3.12.0 | Does MiniDAQ use the affected feature? | Effect on MiniDAQ's requirements |
|---|---|---|
| `operator>>` and `parse` from an `std::istream` without a stream buffer, or with `eofbit` in its exception mask, crash | No: MiniDAQ parses strings | None |
| `merge_patch` and `update` use freed memory when the argument refers into `*this` | No | None |
| `operator[]` with a huge index empties an array instead of throwing | No: arrays are built with `push_back` | None |
| UTF-16 and UTF-32 input with lone surrogates accepted | No: input is UTF-8 text | None |
| `parser_callback_t` keeps discarded values in a parent object | No callbacks | None |
| `patch` operations with invalid paths | No JSON Patch | None |
| `to_msgpack`, `binary_t`, `std::hash`, `ordered_json` fixes | No | None |

Decision: upgrade to 3.12.0 for MiniDAQ 0.3.0 (CR-0002); MDQ-PR-005 is closed by it.
