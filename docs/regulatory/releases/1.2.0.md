# MiniDAQ 1.2.0 release record

The record of SDP section 8 for release 1.2.0: the first milestone toward 2.0.0, with the release tools, the book's quality
checks and errata, and the web edition. Evidence paths
are relative to this directory's parent, `docs/regulatory/`; the files are in `measurements/release-1.2.0/` and were
written by `tools/release_checks.sh` unless the notes below say otherwise. Checked with
`tools/release_record.py check` (Exercise 14.5's `check()`) before the tag was made.

## Release

MiniDAQ 1.2.0, commit 31527cca4e0c387746099a1a8af307cabcc82c56, tag book-v1.2.0

The release checks ran on this commit with a clean working tree (`commit.txt`); the parts that
passed: 1, 2, 3, 4 (`release-checks.txt`), in four parts in one worktree (`commit.txt`,
`commit-part-2.txt` to `commit-part-4.txt`), each at its first attempt. No source of the product
changed since release 1.1.0: `git diff book-v1.1.0 31527cc -- minidaq/src minidaq/include
minidaq/apps recon/src recon/include` is empty. The changes since 1.1.0 are the release tools
(`tools/post_release.py`, the `resume` mode of `tools/release_checks.sh`,
`tools/release_record.py`, used for the first time in this release), a CI job on arm64, the
book's checks (cross references, errata) and corrections (E-002 to E-008), the EPUB's
accessibility metadata, the web edition (`book/tools/web.py`, published under `read/` on the
download page), the license's scope (MDQ-PR-067), the measurements of Chapters 2, 3 and 8
(MDQ-PR-068), the covers and the chapter openers, the triage of five OpenSSL advisories, the
SOUP review for 1.2 and the internal audit of 2026-11-14. The commits on top of 31527cc up to the
tag are this record, its evidence, a row of `tools/release_record.py` and the version strings.

## Verification

Notes on the results:

- Build and tests: `ci/run_all.sh` built all six presets and ran 926 to 936 tests each, none
  failed, the documentation tests among them (`docs.trace`, `docs.baseline`, `docs.risk`,
  `docs.soup`, `docs.anomalies`, `docs.capa`, `docs.changes`, `docs.design_file`, and the new
  `book.xrefs`, `book.errata` and `docs.package_versions`).
- Starters: every starter of the `Release` build fails at least one test and none hangs.
  Exercise 18.3's starter fails in the coverage build and its solution passes
  (`coverage-exercise.txt`).
- Stress: the concurrent tests, 100 repetitions each under ThreadSanitizer: 95 tests, no failure
  and no report.
- Property-based tests: the twelve properties with the wide search, no counterexample.
- Coverage: Clang source-based coverage of the debug tests, per software item (`coverage.txt`):
  90.2% of the lines over all items, every class B item at 75% of its lines or more, as at
  1.1.0. No product line changed, so the review of untaken branches on changed lines has no line
  to review.
- Performance, SRS-PERF-020: the pipeline ran at a median of 35.1 M singles/s in the `hardened`
  build (5 repetitions), 3.5 times the 10 M required (ACC-01: at least 20 M). The same programs
  ran at 41.0 M at 1.1.0: the virtual machine's speed varies between days, and the gate below,
  which runs both releases side by side, finds no change. SRS-PERF-021: the list-mode writer
  wrote 20.6 to 21.7 M coincidences/s with fsync at close (3 runs of 200 M).
- Performance (the gate, CR-0025): release 1.1.0 (book-v1.1.0) and this commit, built with the
  `release` preset and run interleaved (`perf-ab/`): every benchmark at 0.983 to 1.018 of 1.1.0,
  none slower by a significant margin (`perf-gate.txt`). The trend against
  `benchmarks/baseline/book-vm.json` is recorded, not judged (`perf-trend.txt`).
- System tests: 34 test cases on the `release` build, none failed or skipped
  (`system-test-report.md`).
- Soak (SRS-SYS-003): 30 minutes at 1 M singles/s, 1.8 G singles, no loss and no fault; resident
  memory 30.2 to 30.9 MiB with a trend of +0.010 MiB/h (standard error 0.033).
- Latency (SRS-PERF-022): the 99th percentile stayed at or below 10 ms in 180 of the soak's 180
  intervals, at most 4.39 ms; steal time 0.54% on average, 0.93% at most.
- End to end (SRS-SYS-006 to SRS-SYS-008): both acquisitions wrote the reference's records, 33
  of 33 checks passed, and the phantom's image has a radius of 80.25 mm and a center over
  periphery of 1.042 (`e2e.txt`).
- Fuzzing: each of the eight targets ran 600 s from its seed corpus with no crash, leak or
  timeout: config (6.3 M executions, 1,913 coverage points), decoder (15.8 M, 101), raw16
  (645 M, 14), protocol (0.92 M, 2,952), packet (10.8 M, 122), sorter (3.6 M, 324), listmode
  (17.5 M, 184) and calibration (12,058, 1,615) (`fuzz/<target>.txt`).
- Acceptance (`acceptance.md`, `tools/acceptance.py` in the worktree at this commit): 9 of 9
  criteria pass.
- Reproducible build: `tools/repro_check.sh` built the shipped programs of this commit in two
  checkouts of different paths and compared the two product archives (`repro/repro.txt`).
- CI: this commit passed `ci`, `gates`, `codeql` and `pages` (`ci-run.txt`). The release
  commit's own CI run is checked before the tag is made (SDP section 8).

## Known anomalies

Generated from the problem reports by `tools/anomalies.py` ([known-anomalies.md](../known-anomalies.md)):
four open reports, each evaluated again for this release and released with. MDQ-PR-067 and
MDQ-PR-068, reported and closed since 1.1.0, concern the license and the book's measurements.

- MDQ-PR-006 (service, relevant to safety): a port fault is noticed up to 20 ms late. Released
  with: a faulted run is incomplete in its verdict whatever the delay; the server did not change.
- MDQ-PR-007 (sorter, not relevant to safety): the sorter holds its last 104 ns of singles until
  more data arrives. Released with: no coincidence is lost; the end-to-end accounting balances
  every single at the end of a run. Its fix is planned for 1.3.0 (roadmap, Theme B).
- MDQ-PR-009 (sim, relevant to safety): simulation code is linked into the shipped server.
  Released with for a teaching project: simulated data is identifiable in the run record and in
  the diagnostics; the roadmap plans its fix for 1.3.0 (Theme B).
- MDQ-PR-064 (pipeline, not relevant to safety): the end-to-end latency's 99th percentile
  exceeds 10 ms in about one 10 s interval in a hundred on the reference machine, with no change
  to the code. Released with: this release passes ACC-04 with 180 of 180 intervals (at most
  4.39 ms), no single is lost in the soak, and the latency is not a risk control of a hazard.
  The finer measure that the report asks for is still to be made.

## Risk

All 17 hazards of the risk file are closed (`risk/hazards.json`, test `docs.risk`). No hazard's
residual risk depends on a control that is not verified (the trace matrix's risk-control column).
The threat model, version 13, was reviewed for this release: the changes since 1.1.0 are in the
book, its build and the download page (the web edition is static pages built from the EPUB,
served by GitHub Pages, with no part in the running server), the release tools and CI; they add
no element, flow or interface to the running server. The five OpenSSL advisories of 2026-11-10
concern code that MiniDAQ does not use (`security/vulnerability-triage.json`). The overall
residual risk is acceptable under the criteria of the risk management plan, section 3, as judged
by the software lead (the author) for this teaching release; a product release adds the clinical
expert's judgment (assumption: confirm with team).

## SOUP review

2026-11-14, for MiniDAQ 1.2 ([SOUP list](../soup-list.md), version 25, test `docs.soup`): the
trackers and advisories were read again. nlohmann/json 3.12.0 is still the latest release. The
OpenSSL project published advisories on 2026-11-10; the five that the vulnerability scan matched
to the installed `libssl3t64` are triaged not affected (QUIC, AES-GCM-SIV and CMS are not used).
pybind11 3.1.0 has no advisory. The lock file audit reports 30 packages and none with a known
vulnerability (`lock-audit.json`).

## Build

The release is built from the tag with the presets, as the checks did:

```sh
git checkout book-v1.2.0
ci/run_all.sh                                     # the six presets, tests and documentation tests
tools/static_analysis.sh build/clang-release
cmake --preset hardened && cmake --build --preset hardened   # the shipped binaries
tools/repro_check.sh OUT                                     # two builds, compared byte for byte
tools/make_sbom.py --validate -o minidaq-1.2.0.cdx.json
tools/release_checks.sh OUT 600 resume                        # this record's evidence
tools/acceptance.py OUT                                       # the acceptance verdict
book/build.sh all both && book/build.sh boox both             # the book and the solutions
```
