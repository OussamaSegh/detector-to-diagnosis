# MiniDAQ 1.3.0 release record

The record of SDP section 8 for release 1.3.0: the non-breaking items of Theme B of the 2.0.0 roadmap, time markers with
register map 1.2 and signed run records, calibration tables and reports. Evidence paths
are relative to this directory's parent, `docs/regulatory/`; the files are in `measurements/release-1.3.0/` and were
written by `tools/release_checks.sh` unless the notes below say otherwise. Checked with
`tools/release_record.py check` (Exercise 14.5's `check()`) before the tag was made.

## Release

MiniDAQ 1.3.0, commit ced71e9e25fb21a2ff423313e7168f0e4bd4ab3d, tag book-v1.3.0

The release checks ran on this commit with a clean working tree (`commit.txt`); the parts that
passed: 1, 2, 3, 4 (`release-checks.txt`), in four parts in one worktree (`commit.txt`,
`commit-part-2.txt` to `commit-part-4.txt`). Parts 1 to 3 passed at their first attempt; part 4
was stopped by the session's time limit after the fuzz build and ran again in full with
`resume`. Two earlier runs on earlier commits are not evidence of this release: one stopped when
the machine restarted, and one failed the performance regression gate (MDQ-PR-070, fixed in
b9e5e69; the internal audit's O-10).

The changes since 1.2.0: time markers in the readout stream and register map 1.2 of firmware 1.3
with the datagrams the boards sent (CR-0026, ADR 0033, control API 2.5, MDQ-PR-007 closed);
signed run records, signed calibration tables and signed QC reports with Ed25519 (CR-0027,
ADR 0034, threats T-27 and T-54); MDQ-PR-006 decided again; the decoder's fuzz target and the
pre-commit hook (MDQ-PR-069); the decoder's speed (MDQ-PR-070); the SOUP review for 1.3 and the
internal audit of 2026-11-15. The commits on top of ced71e9 up to the tag change no product code:
two tests and the evidence of the coverage review, this record, and the version strings.

## Verification

Notes on the results:

- Build and tests: `ci/run_all.sh` built all six presets and ran 942 to 952 tests each, none
  failed, the documentation tests among them (`docs.trace`, `docs.baseline`, `docs.risk`,
  `docs.soup`, `docs.anomalies`, `docs.capa`, `docs.changes`, `docs.design_file`,
  `docs.package_versions`, `book.xrefs`, `book.errata`).
- Starters: every starter of the `Release` build fails at least one test and none hangs.
  Exercise 18.3's starter fails in the coverage build and its solution passes
  (`coverage-exercise.txt`).
- Stress: the concurrent tests, 100 repetitions each under ThreadSanitizer: 98 tests, no failure
  and no report.
- Property-based tests: the twelve properties with the wide search, no counterexample.
- Coverage: Clang source-based coverage of the debug tests, per software item (`coverage.txt`):
  89.8% of the lines and 79.5% of the branches over all items (90.2% and 79.8% at 1.2.0). Five
  class B items have a lower branch coverage than at 1.2.0, each because new code added
  branches. The review of every untaken branch on the class B lines changed since 1.2.0
  (`coverage-review.md`) found 55 lines in 15 files: two tests were added after the checks
  (tests only), which found MDQ-PR-071; the rest are infeasible or accepted with a reason.
- Performance, SRS-PERF-020: the pipeline ran at a median of 47.7 M singles/s in the `hardened`
  build (5 repetitions), 4.8 times the 10 M required (ACC-01: at least 20 M). SRS-PERF-021: the
  list-mode writer wrote 23.2 to 23.8 M coincidences/s with fsync at close (3 runs of 200 M).
- Performance (the gate, CR-0025): release 1.2.0 (book-v1.2.0) and this commit, built with the
  `release` preset and run interleaved (`perf-ab/`): every benchmark at 0.953 to 1.035 of 1.2.0,
  none slower by a significant margin (`perf-gate.txt`). The decoder, at 0.842 before
  MDQ-PR-070's fix, is at 0.953 (p = 0.11). The trend against `benchmarks/baseline/book-vm.json`
  is recorded, not judged (`perf-trend.txt`).
- System tests: 34 test cases on the `release` build, none failed or skipped

- Soak (SRS-SYS-003): 30 minutes at 1 M singles/s, 1.8 G singles, no loss and no fault; resident
  memory 30.2 to 30.9 MiB with a trend of -0.003 MiB/h (standard error 0.033).
- Latency (SRS-PERF-022): the 99th percentile stayed at or below 10 ms in 180 of the soak's 180
  intervals, at most 3.95 ms; steal time 0.24% on average, 0.62% at most.
- End to end (SRS-SYS-006 to SRS-SYS-008): both acquisitions wrote the reference's records, 35
  of 35 checks passed, and the phantom's image has a radius of 80.25 mm and a center over
  periphery of 1.042 (`e2e.txt`).
- Fuzzing: each of the eight targets ran 600 s from its seed corpus with no crash, leak or

  (870 M, 14), protocol (0.96 M, 2,946), packet (11.9 M, 123), sorter (3.2 M, 324), listmode

- Acceptance (`acceptance.md`, `tools/acceptance.py` in the worktree at this commit): 9 of 9
  criteria pass.
- Reproducible build: `tools/repro_check.sh` built the shipped programs of this commit in two
  checkouts of different paths; the two product archives are identical (`repro/repro.txt`).
- CI: this commit passed `ci`, `gates`, `codeql` and `pages` (`ci-run.txt`). The release

## Known anomalies

Generated from the problem reports by `tools/anomalies.py` ([known-anomalies.md](../known-anomalies.md)):
four open reports, each evaluated again for this release and released with. MDQ-PR-007 was closed
by CR-0026; MDQ-PR-069 and MDQ-PR-070 were reported and closed since 1.2.0.

- MDQ-PR-006 (service, relevant to safety): a port fault is noticed up to 20 ms late. Released
  with: decided again for this release with the cost of the fix weighed; a faulted run is
  incomplete in its verdict whatever the delay.
- MDQ-PR-009 (sim, relevant to safety): simulation code is linked into the shipped server.
  Released with for a teaching project: simulated data is identifiable in the run record and in
  the diagnostics; its fix is a breaking change, planned for 2.0.0-dev (roadmap, Theme B).
- MDQ-PR-064 (pipeline, not relevant to safety): the end-to-end latency's 99th percentile
  exceeds 10 ms in about one 10 s interval in a hundred on the reference machine, with no change
  to the code. Released with: this release passes ACC-04 with 180 of 180 intervals (at most
  3.95 ms), no single is lost in the soak, and the latency is not a risk control of a hazard.
- MDQ-PR-071 (output, not relevant to safety): `verify-run` ends with an exception on a signed
  record whose digest has a field of the wrong type. Found by the coverage review after the
  checks. Released with: the record must first pass the signature check with a key the site
  installed, the server writes the fields with the right types, and the failure is visible, not
  a run believed; its fix is planned for 2.0.0-dev.

## Risk

All 17 hazards of the risk file are closed (`risk/hazards.json`, test `docs.risk`). No hazard's
residual risk depends on a control that is not verified (the trace matrix's risk-control column).
CR-0026 adds SRS-HW-017 to risk control RC-30 of H-01 (data lost without notice): the datagrams a
board sent beyond those the link accounted for are now a loss in the integrity verdict, which
closes the residual of ADR 0018; the sorter's FMEA has a row for a marker that arrives too late.
The threat model, version 16, was reviewed for this release twice: the time markers add no
element or flow (T-16's note says what a forged marker can do), and the signatures add the keys
as assets and the requirements of T-27 and T-54; the gaps of section 7 say what remains when a
site installs no key. The SOUP review for 1.3 found no new advisory. The overall residual risk
is acceptable under the criteria of the risk management plan, section 3, as judged for this
teaching release under the software lead's standing delegation; a product release adds the
clinical expert's judgment (assumption: confirm with team).

## Build

The release is built from the tag with the presets, as the checks did:

```sh
git checkout book-v1.3.0
ci/run_all.sh                                     # the six presets, tests and documentation tests
tools/static_analysis.sh build/clang-release
cmake --preset hardened && cmake --build --preset hardened   # the shipped binaries
tools/repro_check.sh OUT                                     # two builds, compared byte for byte
tools/make_sbom.py --validate -o minidaq-1.3.0.cdx.json
tools/release_checks.sh OUT 600 resume                        # this record's evidence
tools/acceptance.py OUT                                       # the acceptance verdict
book/build.sh all both && book/build.sh boox both             # the book and the solutions
```
