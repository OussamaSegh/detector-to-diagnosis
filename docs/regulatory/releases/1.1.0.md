# MiniDAQ 1.1.0 release record

The record of SDP section 8 for release 1.1.0: the book with an illustrated interior, and the
approval of the controlled documents. Evidence paths are relative to this directory's parent,
`docs/regulatory/`; the files are in `measurements/release-1.1.0/` and were written by
`tools/release_checks.sh` unless the notes below say otherwise. Checked with Exercise 14.5's
`check()` before the tag was made.

## Release

MiniDAQ 1.1.0, commit 9b9e96d5eb6d1e85ef3911d7698406432d4ddde4, tag book-v1.1.0

The release checks ran on this commit with a clean working tree, in four parts in one worktree
(`commit.txt`, `commit-part-2.txt` to `commit-part-4.txt`), each ending with its summary line
(`release-checks.txt`). No source of the product changed since release 1.0.0: `git diff
book-v1.0.0 9b9e96d -- minidaq/src minidaq/include minidaq/apps recon/src recon/include` is
empty. The changes since 1.0.0 are the book (its interior, 231 figures and their scripts, the
index, the wording of the claims it does not check), the documents (the approval of fifteen of
them, the SOUP review for 1.1, the internal audit of 2026-11-10), two checks
(`tools/check_capa.py` for MDQ-PR-065, `tools/design_file.py` for MDQ-PR-066), the workflows that
build the book, and a measurement of Exercise 37.3 (`measurements/ch37/mutants.py`). The commits
on top of 9b9e96d up to the tag are this record, its evidence and the version strings.

## Known anomalies

Generated from the problem reports by `tools/anomalies.py` ([known-anomalies.md](../known-anomalies.md)):
four open reports, each evaluated again for this release and released with. MDQ-PR-065 and
MDQ-PR-066 are closed.

- MDQ-PR-006 (service, relevant to safety): a port fault is noticed up to 20 ms late. Released
  with: a faulted run is incomplete in its verdict whatever the delay; the server did not change.
- MDQ-PR-007 (sorter, not relevant to safety): the sorter holds its last 104 ns of singles until
  more data arrives. Released with: no coincidence is lost; the end-to-end accounting balances
  every single at the end of a run.
- MDQ-PR-009 (sim, relevant to safety): simulation code is linked into the shipped server.
  Released with for a teaching project: simulated data is identifiable in the run record and in
  the diagnostics; Appendix A records the architectural resolution a product would make.
- MDQ-PR-064 (pipeline, not relevant to safety): the end-to-end latency's 99th percentile
  exceeds 10 ms in about one 10 s interval in a hundred on the reference machine, with no change
  to the code. Released with: this release passes ACC-04 (one interval of 180, at 10.16 ms), no
  single is lost in the soak, and the latency is not a risk control of a hazard. The finer
  measure that the report asks for is still to be made.

running server. The overall residual risk is acceptable under the criteria of the risk

## Build

The release is built from the tag with the presets, as the checks did:

```sh
git checkout book-v1.1.0
ci/run_all.sh                                     # the six presets, tests and documentation tests
tools/static_analysis.sh build/clang-release
cmake --preset hardened && cmake --build --preset hardened   # the shipped binaries
tools/repro_check.sh OUT                                     # two builds, compared byte for byte
tools/make_sbom.py --validate -o minidaq-1.1.0.cdx.json
for p in 1 2 3 4; do tools/release_checks.sh OUT 600 $p; done   # this record's evidence
tools/acceptance.py OUT                                         # the acceptance verdict
book/build.sh all both && book/build.sh boox both               # the book and the solutions
```
