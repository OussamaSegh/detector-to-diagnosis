# CR-0003: Control API 1.1, with the status fields versioned

## Description

The control API moves to version 1.1. Its status object has exactly the top-level fields listed
in `status_fields` (`control_protocol.hpp`), each marked as always present or as present while
its part exists, and a test compares real statuses with the list. The server's two fixed error
responses take the version from `api_version` instead of a literal, and `minidaq_ctl` sends 1.1.

## Reason

From Chapter 9 to Chapter 15 the status gained `detector_counters`, `sorter`, `sink_counters` and
`integrity` while every response said 1.0, against ADR 0003. The integrity verdict is a risk
control (RC-01, RC-05), and a client must be able to tell an older server from a status without
it. Without the change, the next field is added silently too.

## Impact analysis

### Requirements

New: SRS-CTL-033 (the status has exactly the fields of its API version). Verification repeated:
SRS-CTL-020 to SRS-CTL-023, whose tests exercise the protocol, and SRS-CTL-030.

### Software items and safety class

Changed: protocol (the version, the list, the fixed responses) and ctl. Both class B; no class or
segregation changes.

### Risk

H-01: the presence of RC-01's verdict becomes part of the interface contract, which supports
RC-05 (software that reads the data checks the verdict first). No estimate changes.

### SOUP

None.

### Interfaces and data formats

The control API becomes 1.1. The major version is unchanged, so 1.0 clients keep working: a
server accepts every 1.x request and clients ignore fields they do not know (ADR 0003). The
status's content does not change; only its version says what it contains. The list-mode format
and the configuration schema do not change.

### Documents

ADR 0013 (new) and ADR 0003 (the current version); the ADR index; SRS version 3; the trace
matrix; MDQ-PR-012 closed; the CHANGELOG.

### Regulatory

The intended use does not change. An interface version that documents what a released interface
already carries is not significant (assumption: confirm with regulatory affairs).

## Verification

ControlProtocol.StatusFieldsMatchTheApiVersion (new), ControlProtocol.VersioningAndMalformedInput,
ControlProtocol.CommandsAndErrors, ControlServer.PipelinedRequestsAndManyClients, the tests docs.trace and docs.anomalies, all six
CI presets and static analysis.

## Decision

Approved by the software lead and the risk manager on 2026-10-25: the change makes an existing
risk control part of the interface contract and is compatible with every 1.0 client.
