# MiniDAQ known anomalies

Generated by `tools/anomalies.py --write` from [the problem reports](problem-reports.json).
Do not edit by hand: the test `docs.anomalies` fails when this file is out of date.

4 open problem reports, 3 of them relevant to safety.

| ID | Item | Anomaly | Relevant to safety | Why | Decision |
|---|---|---|---|---|---|
| MDQ-PR-006 | service | A port fault is noticed up to 20 ms late | yes | Data acquired in those 20 ms after a fault is part of a run that ends in a fault anyway; the fault is reported and the run is not used. No data is presented as complete. | Release with it. Reviewed against the risk file for release 0.3.0: a faulted run is incomplete in its integrity verdict whatever the delay (assess_integrity, RC-01), and H-05 covers the interrupted scan; 20 ms more data in a run that ends in a fault changes neither sequence of events nor harm, so no hazard needs a faster reaction. Chapter 15 was to decide this and did not; the release review did. |
| MDQ-PR-007 | sorter | The sorter holds its last 104 ns of singles until more data arrives | no | The singles are processed at the end of the run, so no coincidence is lost; only their latency grows while the source is silent. | Release with it; time markers from the readout would flush the sorter (Chapter 23). |
| MDQ-PR-009 | sim | Simulation code is linked into the shipped server | yes | A clinical acquisition configured with a simulated source would produce plausible but invented data. The run record states the source type and metadata carries 'simulated', so the data is identifiable. | Release with it for 0.3.0 (MiniDAQ is a teaching project); a product build excludes the simulator or refuses it outside service mode. |
| MDQ-PR-015 | ctl | The class B item ctl has no automated test | yes | The client's certificate check is part of the control of HZ-4 (Chapter 17, CR-0004): a client that sent its token before the check would hand an operator token to an impostor. The check itself is tested (TlsStream.ClientVerifiesTheServer), and the client code that calls it was changed and reviewed under CR-0004, so the gap is in the evidence for the composition, not a known defect. | Release with it until Chapter 19: the system tests run minidaq_ctl against minidaq_server, including a server with a certificate the client must refuse, and close this report. Until then a change to minidaq_ctl.cpp needs a manual test recorded in its change request. |
