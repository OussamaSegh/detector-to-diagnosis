# Exercise 17.1: the requirements proposed for the status page. Use these IDs in threats.json.
DASH-001 The status page shall be served only over TLS 1.3, with the server certificate of the control API.
DASH-002 The status page shall answer only GET /status, and answer every other method and path with 404 or 405 without acting on it.
DASH-003 The status page shall require an observer or operator token in the Authorization header and answer 401 without one.
DASH-004 The status page shall show only the fields of the status object of the current API version, and never a token, a file path or an error's internals.
DASH-005 The status page shall serve at most 4 connections, read at most 8 KiB of a request, and close a connection that has not sent a request within 5 s.
DASH-006 The status page shall record each refused request in the audit trail with the client's address and the token's name.
DASH-007 The status page shall be off by default and bind only where the control API may bind (SRS-SEC-005).
DASH-008 The status page shall send the headers that forbid caching and framing (Cache-Control: no-store, X-Frame-Options: DENY, Content-Security-Policy: frame-ancestors 'none').
