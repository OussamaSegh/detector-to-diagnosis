# Exercise 16.3: notes

**Bad news before the audit.** Record it first: a problem report that says the SDP requires a
reviewed pull request for every change and that the sorter's last change had none, with its
evaluation (the change was verified by the full CI, so the risk is a missed design error, not an
untested one) and the action you propose. In the audit, answer the question that was asked, say
that you found the gap yourself, and show the record. A nonconformity that the organization has
found, recorded and is correcting is evidence that its quality system works; the same gap found
by the auditor, after an answer that hid it, is a finding against the system and against every
other answer you gave.

**Why the rules.** A hedge invites the next question ("why only probably?"), an answer without
evidence is an opinion, and a directory is a place to look, not a record. Short answers keep the
auditor asking about the sorter and not about the answer.
